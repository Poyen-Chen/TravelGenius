## 已選定的呈現方式

取代 PD-038 僅功能相似的呈現。對齊城市＋日期、星期、完整天數、圖示、字級、24px 分區間距、淡色每日列、提醒、收合說明、取得時間與保存語意。手機底部面板／桌面限寬視窗是容器差異，不另改資訊順序。新查詢採 App 的降雨 ≥50%、炎熱 ≥30°C，既有資料與清單不重算；舊摘要保留舊判定標示。詳細落地規格見 `web/packmon/docs/weather-app-parity.md`。

本次先提供本機候選並對照 App 實際畫面，等待視覺確認再發布；正式站目前仍是版本 7。

### PD-038：PWA 選擇性同步（2026-09-25）

刻意保留差異：PWA 多城市、40% 降雨與 28°C 炎熱門檻、手動更新後合併新物品。更新按鈕明确提示影響，查看詳情不觸發更新。離線快取版本 v10。驗證：每日資料、舊資料、季節備援、多城市、HTML 跳脫、原有推薦測試；人工確認建立／預覽表單不因展開詳情遺失、保存行程詳情與更新操作分開。

### PD-037：每日清單詳情（2026-09-24）

使用者選定第二張詳情概念圖。大型可捲動面板依序呈現城市／日期、建立時參考與涵蓋範圍、精簡摘要、每日日期／溫度／降雨機率、打包提醒、預設收合的資料說明、取得時間與来源。降雨機率 ≥50% 的列用淡橘底色和實心水滴提示；星期使用目的地日曆。輔助使用大字級改直排列，不縮小文字。

僅顯示保存的實際每日數據，缺少日期另外提示並在說明列明；季節參考不顯示每日假數值。不新增即時查詢或清單更新。此規格取代 PD-036 的中型文字面板，主卡保持不變。

驗證：真實數值／高降雨列、說明展開收合、長內容捲動／關閉、季節資料缺省、大字級，並確認清單數量與勾選不變。

### PD-036：打包提醒優先（2026-09-24）

使用者選定方案 2。共用天氣卡改為「打包提醒 → 預報溫度／降雨 → 涵蓋範圍 → 查看詳情」，沿用 Packmon 主題。提醒由既有冷／熱／雨標籤產生，不宣稱物品已加入。無預報時不顯示溫度或降雨天數；部分預報明示涵蓋天數，季節參考標示非預報，保存行程標示建立時參考。

詳細日期、取得時間、降雨定義、季節依據、失敗原因與授權連結移入可捲動的中／大型底部面板。主卡仍保留來源，窄螢幕或大字級時數據改為直排。共用於建立／預覽／總覽／打包，不變更預報來源、規則、保存資料或清單；PWA 本次不修改。

人工驗證：雨天提醒、詳情開關、遠期行程季節標示、部分涵蓋與大字級換行，以及開關面板後勾選／數量不變。仍待第 4 階段人工驗收。

## 產品流程

1. 基本資料具備城市及有效日期後開始查詢；避免每個無效中間輸入發請求。
2. 進入清單預覽前確定這次使用的天氣依據。查詢有等待上限，失敗可採季節備援繼續，不阻擋建立。
3. 預覽顯示完整預報／部分預報／季節推估及來源、取得時間、涵蓋範圍。使用者開始取捨後，晚到結果不得默默更改內容。
4. 最後一步保存使用者確認的清單與建立時天氣依據；失敗不導向成功頁。完成後不再自動重新推薦。
5. 舊行程允許讀取／顯示天氣，但讀取不得修改清單。既有「重新產生清單」如何使用保存天氣及舊行程無快照時的行為，實作前須明確記錄；不能暗中引入第 5 階段的新更新互動。

## 建議資料與服務契約

- 查詢輸入：provider、穩定城市識別、座標、目的地 timeZoneID、旅行當地 startDate／endDate。行程日期是日曆日期，不可單純以秒數除以 86400 跨越日光節約時間。
- 每日結果：當地日期、有效最高／最低溫、降雨機率及缺漏欄位；缺漏不可當作 0°C 或 0% 降雨。檢查重複、日期範圍、單位與有效數值。
- 結果描述：requestedDates、coveredDates、missingDates、fetchedAt、provider、coverage（完整／部分／無預報）、freshness、failureReason、季節來源／版本。
- 推薦輸入：將每日預報與未涵蓋日期的季節依據轉成規則可用的事實；保留來源，依 catalog ID 去重。不要把季節推估合成假每日預報或精確雨天數。
- 持久化：保存建立時實際使用的天氣／季節依據，採版本化且舊資料可缺省的格式；具體 SwiftData 欄位在實作前定稿。舊行程不杜撰歷史天氣，不因新增欄位重算清單。使用副本驗證升級與另程序重開。
- 分層：WeatherKit adapter → 可測試天氣結果 → 季節備援／推薦轉換 → 建立草稿；View 不直接把網路結果套入已保存清單。測試注入時鐘、天氣提供者及固定 fixture。

## 快取、請求與失敗

- Key 至少含來源、城市座標、旅行日期及目的地時區；schema／來源版本變更需失效策略。相同進行中查詢可合併，不把取消誤記為無天氣。
- 六小時有效期沿用為初步方案，尚待定稿；過期資料是否可展示及最長期限需明確決策，不無限沿用、不標成最新。
- 切换目的地／日期取消舊工作，回應到達再比對查詢身分；只取消並不足以保證舊結果不寫入。
- 區分斷網、逾時、權限／服務設定失敗、無預報範圍、資料缺漏。使用者看到簡潔備援說明，診斷可辨識原因但不得記錄憑證或敏感資料。
- WeatherKit 未開通不能以備援 UI 當成串接成功；測試 fixture 不能冒充真實連線證據。需要外部帳號設定時另請使用者處理，不自動購買或變更會員方案。

## 季節資料與平台界線

只涵蓋目前支援城市；先審核 PWA 已有資料及來源，可重用概念／資料，不盲搬推估。每筆記錄城市／區域、月份、冷熱／降雨特性、來源與整理日期；跨月涵蓋所有相關月份。找不到可信資料時保持明確的資料不足狀態，不借用不相符首都氣候。

PWA 暫不切換供應商、不新增網站後端；其 Open-Meteo 使用仍受自身方案限制，不能因 iOS 改 WeatherKit 而宣稱網站可免費商用。適合共用的門檻與資訊語意需評估對齊，但不同來源不承諾輸出完全相同。

## 候選實作（PD-034）

- `WeatherRequest` 保存 picker 的日曆年月日，轉入目的地 IANA 時區；以 Gregorian Calendar 加日，支援 DST，不用固定秒數算天數。範圍最多 3,660 日作為畸形輸入防護，無效範圍在建立頁提示並停用下一步。
- `WeatherDay` 檢查日期唯一、範圍、有限溫度及 0...1 機率；不完整或無 attribution 的日期不用於預報。門檻保留 App 的 30°C／10°C／50%，季節推估不套成實際數值。
- `PackingWeather` v1 保存 request／有效 days／fetchedAt／季節 profile 副本／failure／Apple attribution URLs。未涵蓋日期以日期差集計算，涵蓋跨月。新增 Trip 字串欄位預設空；decode／version／內容檢查失敗不重算，舊資料不回填。建立儲存仍在隔離 ModelContext 中完成。
- `WeatherDraft` 為主執行緒 Observable 狀態；300ms 去抖、同一查詢不重複啟動、10 秒獨立 deadline，不等待不合作的 SDK 取消；UUID revision 與查詢比對避免晚到回應寫入。離開建立頁取消；清單預覽採固定結果。返回未改條件保留；改條件重產推薦且保留已排除 ID／自訂／常備草稿。
- `WeatherService` 使用 WeatherKit 的每日日期區間（結束日加一日），包含來源聲明查詢；只快取有有效預報的結果。Key 包含供應商版本、城市 ID、座標、日期、時區；六小時且同目的地當地日內可用，失敗不取過期資料。成功保存時清除過期 v1 快取。不共用舊 Open-Meteo 快取。
- `seasonal_weather.json` 包含 11 城市、各月份 heuristic、來源及整理日期；東京／大阪／京都與首爾／釜山使用各自國家的廣域季節概述（不宣稱已取得城市實測常年值）；紐約與洛杉磯分開、越南南北中部分開。峴港採官方城市指南的 11–2 月雨季說法；其他官方旅遊頁月份略有差異，因此畫面標示為概略打包參考而非預報。未另做氣象站資料統計，後續可獨立改善，不擴大現在的精確度宣稱。
- `PackingWeatherCard` 共用於建立基本資料／預覽／保存後打包／總覽。顯示實際預報日期、缺漏日數、來源與時間；保存後明示非最新。Apple mark 由 attribution URL 載入，網路缺失時文字 fallback；正式上架仍須實機確認來源標示可用性。
- 既有打包頁不再啟動網路或自動合併。手動重新產生使用保存快照；舊行程保留 legacy month policy，不新增日期編輯或更新预覽。首頁／總覽的虛構冬季文案移除。
- 不讀裝置定位；WeatherKit 查詢傳送所選城市座標及日期。不新增密碼／API key、帳號、背景權限或 PWA 後端。

### 開通與真實驗證待辦

**PD-035 更新：以下為未來切換 WeatherKit 的待辦，不是現在使用 Open-Meteo 的前置條件。** `WeatherService.activeProvider = .openMeteo`；保留 WeatherKit 分支但目前不呼叫，預設 entitlement 也暫不要求 WeatherKit。切換必須同時設定供應商、entitlement、Team／App ID，不能只改一行就宣稱已上線。

## 驗證與交付

工程：完整／部分／遠期、缺漏與非法值、斷網／逾時／未開通、快取命中／過期／日期變更、取消後晚到、台灣查美國／跨月／日光節約時間、預覽凍結、已保存清單不變、資料升級／重開。保留階段 2／3 的打包與排除保護回歸。

人工：近期看到範圍及推薦；部分預報與推估分開；遠期／斷網仍能建立；切換城市不殘留舊結果；預覽取消雨具後建立不補回；重開舊行程內容與勾選／自訂／數量不變。分別記錄真實 WeatherKit 成功證據與 fixture 測試，不互相替代。

不包含：背景通知、修改行程日期的新介面、既有清單更新預覽、PWA 全面改接 WeatherKit、匯入匯出。完成候選後列出範圍、測試限制、操作與預期，等待人工驗收；通過才發布階段 4 tag。
