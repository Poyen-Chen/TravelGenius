## 階段 2：穩定目錄與建立流程

- 狀態：已驗收；PD-025～027；功能提交 `6d15a92dbf9a5fe233cc0335e5ed9c7f2f4032b0`。
- catalog ID 為物品身分；舊名称相容、未知舊物品保留、排除 ID 與舊名稱相容。規則與資料隨 App 發布，不從外部 main 自動熱更新。
- 重新產生採合併而非清空重建；保護已打包、自訂、手調數量及排除；重複操作不可產生重複品。詳見目錄契約及 PackingRegression 測試。
- 三步建立：基本資料 → 採納推薦／自訂用品 → 提醒。完成才保存，成功後直接進入該行程打包頁；採納不代表已打包。取消草稿不建立行程，儲存失敗不假裝完成。
- 入口：PackingListGenerator、TripCreationFlowView、PackingItem、Trip、packing_items／packing_rules。
- 已知歷史限制：打包頁會查天氣並自動合併，造成預覽與最後清單可能不同；此限制到階段 3 仍存在，由階段 4 處理。沒有可供驗收的編輯行程日期入口。
- 回退：`packmon-ios-stage-02-accepted`。

## 階段 3：個人需求、常備清單與快照

- 狀態：已驗收；PD-028～032，PD-031 取代 PD-028 的設備／需求排除及 PD-030 的分組首頁。
- 最終功能提交 `4fc8565dae27942bdb1b1043e267f50984ca6f51`；驗收提交 `4c4a6fb4ddee5033992ced6813523ac34dfee77c`。
- 我的：吉祥物與數量摘要 → 常備清單 → 個人打包需求 → 外觀。外觀保留 App 即時套用；個人需求需儲存，取消不改設定。首次引導共用需求設定。
- 六種設備：手機、筆電、平板、相機、手錶、耳機。六種需求：眼鏡、隱形眼鏡、保養、生理用品、常備藥、讀物。設備周邊依目錄 ID 帶入；共用充電用品去重。新行程不再依人口特徵推測醫藥或用品。
- 風格：輕便每日換洗最多 4；一般／準備齊全依天數最多 99；full-only 備用品只在齊全加入。舊快照保留原有解讀，不追溯套用新政策。
- UserPreferences 的 devices／needs 為可選欄位以相容歷史快照；nil 與明確空選擇不可混同。新行程使用 forNewTrips；舊行程缺少快照時保存當下偏好一次，不聲稱還原歷史。
- Trip.packingPreferencesRaw 固定當趟設定；改全域設定不重算舊行程。快照毀損不得以目前設定做破壞性替代；升級保存失敗必須提供重試。
- PackingStaples 使用版本化本機儲存；名稱非空、數量 1–99、名稱／catalog 別名去重。unitWeightKg 選填、有限數值 0–100；空白代表未知，不估算重量。
- 新行程複製常備品，匹配推薦時使用常備數量且只出現一次；保存為受保護自訂物品。後續修改／移除全域常備不影響舊行程。
- 打包列星號開啟常備編輯草稿，儲存才加入。移除常備須確認，只改全域清單，不刪當趟物品。一般自訂品不自動學習成常備。
- 已存行程／物品／常備的移除使用主題確認 sheet；開啟、取消、下拉關閉不刪資料。回程重設／放棄草稿不是本次移除樣式範圍。
- 工程證據：7,200 組歷史比對、192 組需求與風格、設備單選、重量／快照／真實 SwiftData 升級與重開；具體日志及 UI 覆蓋限制見階段計畫，不新增未執行的測試宣稱。
- 不包含：活動／住宿／洗衣、跨端同步、匯入匯出、3D、自動估重、天氣重寫。
- 回退：`packmon-ios-stage-03-accepted`。本機 `web/` 原本未追蹤；PWA 修改未部署，也不包含在這個 iOS tag。

## 推薦引擎現代化候選

- 狀態：PD-046／PD-047 已授權實作，本機候選待人工檢視，尚未接受推薦內容品質。
- 規格：[推薦引擎現代化規格](recommendation-engine-modernization-spec.md)。它明列舊版、改版前現況、目前候選與仍需決策的差異。
- 新行程只用明確設備／需求、三種打包風格、目的地、天氣及行程情境；年齡、性別、旅伴、旅行經驗只供舊快照解碼。
- 活動、住宿、洗衣存成版本化當趟快照。出發國固定台灣，`originCity` 留空，不把台北誤當全台灣。
- 既有行程更新先產生唯讀增／減／移除差異；使用者逐項確認後才寫入。採用新版設定也只在這次確認成功時保存。
- 此候選原先只增加洗衣用品、不限制衣物數量；該內容已由 PD-050 的衣物減量政策取代。`fullOnly`、已打包品警告與舊行程重複詢問等引擎原則仍保留，實際活動／住宿物品改以 V1 目錄規格為準。
- 原推薦引擎候選未同步 PWA；後續 V1 目錄候選已依 PD-052 同步兩端。五國內容研究由另一項工作補上；出發機場選項等確認確有推薦差異後再評估。

## V1 最小充分物品目錄

- 狀態：目錄內容已人工驗證；PD-049～PD-052；iOS 與 PWA 實作候選完成，待人工驗收與部署決定。
- 61 項是所有支援情境的 active identity 總數，不是單趟清單長度。一般國際旅行從 9 項基本物品開始，再依明確設備／需求、目的地、天氣、活動、青旅及洗衣條件加入。
- 既有但未納入新推薦的 ID 保留解碼與既有行程顯示，不刪除、不重用。藥物、視力用品、急救、專業裝備及長尾需求由使用者加入自訂或常備清單。
- 途中洗衣會降低日常衣物數量，取代先前「只增加洗衣用品、不減量」的 iOS 政策。精確上限及不受影響的特殊服裝見 [完整規格](packing-catalog-v1-spec.md)。
- iOS catalog version 2 保留 95 筆定義並以 61 個 `activeItemIDs` 限制新版推薦；PWA 使用相同 61 項 active identity。歷史快照與既有行程不靜默改寫。
- 新版行程輸入只保留會改變清單的活動、青旅及洗衣選項，另以「自駕」明確觸發駕照文件。`local-cash` 尚無可靠觸發，不依國家刻板印象產生。
- 工程驗證已通過 iOS 回歸腳本、完整 device build、PWA 59 項測試與語法檢查；尚未等同人工驗收。
- V1 目錄範圍不新增獨立的行前確認／提醒功能。最終物品圖片仍須等本候選人工驗收後製作。
