## 原設計與問題

App 的重新產生會直接合併、可能移除不再適用的未打包自動物品；舊編輯入口也可能觸發合併。PWA 更新天氣／重新產生直接更動清單，沒有逐項採納。這些入口改為明確預覽再新增，不清空重建。

## 目前行為

1. 打包頁「更新打包建議」主動查詢現有目的地及日期，沿用供應商／快取／逾時規格。
2. 原頁展開淡橘色「建議補入」，原有清單仍在下方。不開新的 modal。
3. 查詢可取消或先用季節參考。新天氣只用於這次建議；原建立時天氣快照保持原樣。本次依據可展開查看來源與詳細資料。
4. 只列出既有清單沒有、且未被排除的物品，預設勾選；列出名稱、建議原因及數量。全取消時加入按鈕停用。沒有新項目時顯示空狀態。
5. 確認時再核對現有物品／排除，避免重複或補回剛移除的用品。既有 UUID、數量、重量、原因、自訂及打包狀態不修改。未勾選只代表本次略過，不新增永久排除。
6. 取消、離開頁面及晚到回應不改清單。只有存檔成功才顯示加入完成；失敗保留錯誤與重試入口。

## 邊界與平台差異

- 不新增行程日期／個人需求編輯畫面、活動、住宿、洗衣、完整增刪差異預覽。既有 App 行程編輯不再自動合併清單。
- App 採穩定 catalog ID／舊名稱辨識與当趟偏好快照；PWA 沿用自身名稱身分與既有推薦引擎，查詢時凍結該次參數，不全面移植 iOS 資料模型。
- PWA 沿用既有多城市、圖卡／3D、分包；建議是同一個文字勾選區塊，不加入新 3D。既有安排設定保存後只開啟建議；取消建議不撤回已明確儲存的安排。
- PWA 先保存新的完整資料副本成功後才更新畫面；跨分頁資料更新使舊建議失效。App 插入前暫停 autosave，save 失敗只刪除本次插入，不 rollback 其他操作。
- 不改全域常備／需求、不迁移資料、不改公開權限。本階段候選仍需人工通過後才能建立 accepted tag。

## 驗證

- Swift：7,200 歷史案例、舊資料副本升級與另程序重開；新測試涵蓋唯讀提案、選取新增、排除變動、自訂／已打包／數量保護、零選取與重複採納。
- PWA：53 項自動測試，包括原物品及分包保留、排除／重複及本次零選取。
- 人工：打包頁更新 → 切换勾選 → 取消，確認原清單不變；重開更新只勾一項加入，核對新增數與原有數量／勾選；再更新不得重複；先前排除不補回；離線或遠期可用季節參考。
- 實際存儲空間耗盡與實機 VoiceOver 尚未注入驗證；不得把自動測試當成人工驗收。
